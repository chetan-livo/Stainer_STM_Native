# Master application port log (milestone 4)

**Source:** `RadoratoryTechnologies/Livo-Stainer`, branch `perf/timer-step-engine`, commit `271a10b`. This is the Arduino Master V2.6.0, including the Task 1 timer step engine and loop fixes.

## What was copied

All application sources (`LivoStainer/*.cpp|h|inc|ino`, 93 files) and the vendored Adafruit DHT driver (`src/AdafruitDHT`, MIT) went into `firmware/App/`. The application stays multi-board (`#ifdef` per PCB). Only the Master configuration builds it so far; the other boards keep the bring-up app until their milestones (`PORTED` in `tools/generate_cubeide_project.py`).

## Behaviour differences

**Intended or improved:**

- **Step timing** is generated by the timer interrupt: Task 1 behaviour, with the native TIM7 handler. The bed T motor stays polled.
- **`analogRead`** returns the latest DMA scan sample (at most about 20 µs old), with the same ADC settings, instead of a blocking per-call conversion.
- **I2C:** `endTransmission(false)` + `requestFrom()` is a real repeated-start read (STM32duino behaved the same way). The receive buffer is 128 bytes.
- **USB console output** is discarded while no terminal holds DTR, so the loop never waits on an absent host.
- **`ID`** reports `BUILD:NATIVE <date> <time>`; `FW:V2.6.0` is unchanged.

**Proven identical by host tests (`tools/run_host_tests.ps1`):**

| Item | Evidence |
|---|---|
| `String` | 205,379 differential checks against the STM32duino 3.0.0 `String` |
| `Print` number/float output | 445,541 bytes compared against STM32duino `Print` |
| TMC2209 datagrams and reads | Against TMCStepper 0.7.3 |
| Step timing | Against AccelStepper 1.64 |

Two `String` cases differ deliberately: `NaN`/`inf` formatting and `startsWith(text, offset)` with an over-long text, where the Arduino version reads past the buffer (found by AddressSanitizer). The firmware does not use either.

**Identical by construction:**
- clock trees;
- ADC channel, timer channel and I2C pin mapping (generated from STM32duino's tables);
- PWM frequency and duty arithmetic;
- UART baud and framing.

## Findings in the original code (unchanged)

The native build compiles the application with `-Wall -Wextra`, which the Arduino build did not. That produces 52 warnings, all in unmodified application code:
- 16 unused parameters, 15 unused variables, 3 unused functions;
- 7 signed/unsigned comparisons, which behave the same because `size_t` is `unsigned int` on ARM, as Arduino's `String::length()`;
- 6 member-initialisation-order warnings;
- 3 misleading indentations: `DiagnosticFrame.h:19`, `MasterBedProduction.inc:58/211` (style only);
- 2 possible `snprintf` truncations of diagnostic labels (`AnalogSensorReader.cpp:76`, `HallSensorModule.cpp:228`).

They are left as-is to keep the port behaviour-identical.
