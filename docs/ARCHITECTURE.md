# Architecture

## Layers

```
App/        application: command parsing, motion, bed scheduling, diagnostics
Boards/     per-board pins and peripheral assignments
Devices/    external chip drivers (TMC2209; later VL53L0X, DHT11, NeoPixel)
Platform/   native drivers with an Arduino-shaped API (Print/Stream, pinMode, millis, ...)
Drivers/    ST HAL/LL + CMSIS (unmodified)
Middlewares ST USB device library, CDC class (unmodified)
```

The platform keeps the API the existing firmware already calls (`Serial.print`, `digitalWrite`, `millis`, `Uart::begin`). The application classes can therefore be moved across mostly unchanged and verified against the Arduino build. Each driver is native: it owns its peripheral registers and interrupts, with no hidden re-initialisation per call.

## One project, many MCUs

| Item | How it varies |
|---|---|
| Device header / HAL | `STM32F446xx`, `STM32F407xx` or `STM32F401xC` define per configuration |
| Startup file | `Platform/Startup/startup_*.s`; the other two are excluded per configuration |
| Linker script | `Platform/LinkerScripts/*.ld`, selected per configuration |
| Board code | `Boards/<Board>/`; other boards' folders are excluded per configuration |
| Board identity | The same board define as the Arduino sketch (`Stainer_Master_PCB`, ...) |

`tools/generate_cubeide_project.py` is the single source of these settings.

## Clock trees

These are identical to the STM32duino generic variants the boards run today, using HSI only with no crystal assumed:

| MCU | SYSCLK | APB1 / APB2 | USB 48 MHz |
|---|---|---|---|
| F446ZE | 180 MHz (PLLR, overdrive) | 45 / 90 MHz | PLLSAI-P |
| F407VE | 168 MHz | 42 / 84 MHz | PLLQ |
| F401RC | 84 MHz | 42 / 84 MHz | PLLQ |

## Conventions

- **Pins.** `PA0` = 0x00 through `PI15` = 0x8F (port << 4 | pin), stored in `uint8_t`. `PX_n` names are aliases. The existing board headers compile unchanged.
- **Interrupt priorities** (`platform_irq.h`, group 4):

  | Priority | Source |
  |---|---|
  | 0 | SysTick |
  | 1 | step timer |
  | 2 | UART |
  | 3 | USB |
  | 4 | I2C |
  | 5 | ADC/DMA |
  | 6 | EXTI |

  New drivers must use this table.
- **Serial buffers.** UART RX and TX are 1 KiB each; USB is 1 KiB RX and 2 KiB TX. Writes never block for a disconnected USB host. UART writes block only while the transmit buffer is full.
- **Files that would shadow C headers** on Windows' case-insensitive filesystem are avoided (`Timebase.h`, not `Time.h`; `WString.h`, not `String.h`).
- **Errors.** `platform_error()` records the code in `platform_last_error`. Debug builds stop at a breakpoint when a debugger is attached; Release builds reset.
- **C++.** gnu++17, no exceptions, no RTTI, no thread-safe statics. Heap via newlib-nano `_sbrk` (`sysmem.c`).

## Drivers (milestone 2)

| Driver | Behaviour | Difference from STM32duino |
|---|---|---|
| `analogRead` | ADC1 (and ADC3 on F446 port F) continuously scans every pin read so far; DMA writes the latest samples. Same settings: PCLK2/4, 15-cycle sampling, 12-bit | Returns the newest sample (at most about 20 us old) immediately, instead of re-initialising the ADC and converting on each call (about 30 us blocking). A pin's first read waits for one fresh scan |
| `analogWrite` | 1 kHz, 8-bit, PWM mode 1, `CCR = (ARR+1)*value/max`, same prescaler formula. Pins without a timer are driven digitally (>= half scale is HIGH) | Only the pin's own output (CHx or CHxN) is enabled, so a GPIO sharing a TIM1 channel (e.g. PB14 with PE11) is never mirrored |
| `TwoWire` | Blocking master transfers, 100 ms timeout, Arduino `endTransmission` codes. Slave via HAL listen mode | `endTransmission(false)` + `requestFrom()` becomes one repeated-start register read (1-2 byte register). Adds `recoverBus()` (9 SCL clocks + STOP) |
| `attachInterrupt` | EXTI line per pin number, `IRQ_PRIO_EXTI` | — |
| `StepEngine` | Port of Livo-Stainer `perf/timer-step-engine`: 50 kHz TIM7, AccelStepper-equivalent planner, holds and 50 ms service lease | Native TIM7 handler instead of the HardwareTimer callback chain |
| `Watchdog` | IWDG, timeout in ms, frozen while a debugger halts the core in Debug builds; reset cause captured at boot | Not started by default; enabling it in production is still an open decision |

Pin -> peripheral tables (`Platform/Src/PinMaps.cpp`) are generated by `tools/generate_pinmaps.py` from the default entries of STM32duino's `PeripheralPins.c` (ST, BSD-3) for each part. This keeps every ADC channel, timer channel and I2C pin identical to the Arduino firmware.

## Compatibility pieces (milestone 3)

| Piece | Replaces | Notes |
|---|---|---|
| `WString` | Arduino `String` | Own implementation of the subset the firmware uses. Arduino semantics: lower-case hex, atol `toInt()`, out-of-range indices give empty results |
| `Devices/Tmc2209` | TMCStepper 0.7.3 (MIT) | Same method names, shadow registers, defaults and current arithmetic, so datagrams are byte-identical. The 2 ms `replyDelay` after each access is kept for parity; motion no longer stalls on it |
| `MotionPlanner` | AccelStepper 1.64 (GPL-3.0) | Clean-room trapezoid from D. Austin's published equations. Step timing equals AccelStepper's, verified step for step |
| `StepEngine` / `IsrStepper` | AccelStepper `run()` in loop | 50 kHz TIM7 interrupt using `MotionPlanner` + `StepCountdown` |
| `PolledStepper` | AccelStepper `run()` | One step per call, timing from the last actual step; for the bed T motor and the `STEPISR 0` fallback |

## Host tests

`tools/run_host_tests.ps1` builds `tests/host/` with clang (LLVM-MinGW), using AddressSanitizer, UBSan and `-mno-ms-bitfields`. The last flag makes struct bitfields follow ARM GCC's layout rather than MSVC's; with MSVC layout TMCStepper's own register structs come out wrong on the host. Equivalence tests compile TMCStepper and AccelStepper from the local Arduino sketchbook as references, linked only into the test programs and never into firmware. They are skipped if the libraries are absent.

## USB console

ST VCP VID/PID 0483:5740 (same as STM32duino). Product string "Livo Stainer <Board>". The serial number is the MCU's 96-bit unique ID. Only PA11/PA12 are configured: no VBUS or ID pins, because PA9/PA10 carry board functions (PA10 is Gantry NRST on the Master).
